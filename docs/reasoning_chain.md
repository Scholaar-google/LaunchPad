# 长链推理五步结构规范与示例

## 设计原则

综合 Agent (Synthesis) 的推理过程**必须**按以下五步结构展开，每步结果写入 `state.reasoning_chain`。

**禁止跳过任何一步**，即使前序步骤的结论已经非常明确。

## 五步推理结构

### 第1步：汇总层 (Summary Layer)

**目的**：提取三个并行 Agent 的核心结论与置信度，确保后续推理有清晰的信息基线。

**输出格式**：
```
可行性分析结论：[结论]（置信度：X%）
资源评估结论：[结论]（置信度：X%）
风险评估结论：[结论]（置信度：X%）
信息完整度评估：[完整/部分缺失/严重缺失]
```

**示例**：
```
可行性分析结论：技术可行（置信度：85%）
资源评估结论：当前资源可支撑，需增加 2 名后端开发（置信度：70%）
风险评估结论：中等风险，主要风险为第三方 API 依赖（置信度：75%）
信息完整度评估：部分缺失（缺少具体的技术栈偏好信息）
```

### 第2步：冲突识别层 (Conflict Identification Layer)

**目的**：调用 `conflict_detector` 工具，找出三个维度结论之间的矛盾点。

**冲突类型**：
- 可行性 vs 资源：可行但资源不足
- 可行性 vs 风险：可行但风险过高
- 资源内部矛盾：团队规模与工期不匹配
- 覆盖度缺失：某个维度遗漏的关键问题

**输出格式**：
```
发现 [N] 个矛盾点：
1. [矛盾主题]：[源A结论] vs [源B结论]
2. ...
无矛盾点。  （如无矛盾）
```

### 第3步：路径推演层 (Path Exploration Layer)

**目的**：针对每个矛盾推演 2~3 种解决路径，评估每条路径的优劣。

**每条路径包含**：
- 路径描述
- 预期效果
- 实施难度
- 风险/收益

**输出格式**：
```
矛盾1：[主题]
  路径1：[描述] → 优点：[...]/缺点：[...]
  路径2：[描述] → 优点：[...]/缺点：[...]
  路径3：[描述] → 优点：[...]/缺点：[...]
推荐路径：[理由]
```

### 第4步：决策层 (Decision Layer)

**目的**：结合企业战略优先级（从配置文件读取），选择全局最优路径，做出最终决策。

**决策标准**：
1. 是否符合企业战略方向
2. 风险是否在可接受范围
3. 资源投入是否合理
4. 是否满足核心业务目标

**输出格式**：
```
企业战略对齐度：[高/中/低]
核心业务目标满足度：[高/中/低]
综合风险评级：[低/中/高/极高]
最终决策：[立项/缓议/拒绝]
决策依据：[...]
```

### 第5步：输出层 (Output Layer)

**目的**：生成完整的最终建议，包括关键假设和不确定项清单。

**输出格式**：
```
最终建议：[立项/缓议/拒绝]
建议理由：[...]

关键假设：
1. [假设描述]（状态：有效/需验证）
2. ...

不确定项：
1. [不确定项描述]（影响程度：高/中/低）
2. ...

下一步行动：[...]
```

## 注意事项

1. 每步必须写入 `reasoning_chain`，即使内容为空也需记录"无数据"
2. 并行 Agent 返回 `None` 时，汇总层标注"超时或失败"
3. 前端 `ReasoningPanel` 通过 SSE 实时更新，后端每步完成后立即 flush
4. 五步推理是**强制要求**，langgraph 工作流不会拦截跳过步骤的 Agent，但 code review 和测试会检查
